SLIDE 2 · IDEA TITLE

Idea: a neural transceiver that sends meaning, not audio

Template pointers: proposed solution, detailed explanation, how it addresses the problem, innovation and uniqueness. Use the three blocks below as three columns or three rows of bullets, plus one small diagram (the one-line pipeline).

Suggested idea title

iTantra: offline multilingual voice walkie-talkie that transmits text and speaks it back

Proposed solution

  • Android app with on-device STT and TTS for Hindi, Gujarati, Marathi, Kannada, Malayalam, Tamil, Telugu, Odia, Bengali and English.
  • Sender: push-to-talk, pause detection cuts a sentence, STT turns it into text.
  • Only the text goes over Wi-Fi, Wi-Fi Direct or Bluetooth LE: a median of 62 bytes per sentence in compact binary form.
  • Receiver: speaks it as a voice note; alerts play at maximum volume on the alarm channel and cannot be interrupted.
  • One-tap SOS sends a spoken request with GNSS/NavIC coordinates.
  • PTT off = phone-call mode (hands-free, both directions).

How it addresses the problem

  • Voice is data-heavy. A 3-second sentence is about 96 KB as raw audio and 4.5 KB as Opus; iTantra sends about 62 bytes.
  • Fits links that cannot carry voice: BLE, congested Wi-Fi, LoRa bridges (~0.3–5 kbps).
  • Output is still speech, so people who cannot read are included.
  • Everything runs offline on the phone: no tower, no internet, no cloud API.
  • Open-source models and runtimes only.

Innovation and uniqueness

  • Speech → text → speech as a "semantic codec" for low-bitrate radio.
  • Per-script dictionary compression: 524-byte JSON frames shrink to 62 bytes.
  • Trusted alerts: ALERTs are Ed25519-signed; an unsigned ALERT from an unpaired phone plays as a normal message.
  • Live captions on both phones while the speaker is still talking.
  • Self-healing link: LAN → Wi-Fi Direct → BLE, with the same packets reaching an ESP32/LoRa bridge.
  • Planned: on-device translation so a Tamil listener hears a Hindi message in Tamil, and sender-voice rendering.

Methodology (six steps)

  1. Model selection against three hard limits: covers all 10 languages, open licence, runs on a phone CPU.
  2. Conversion: export to ONNX/GGUF, quantise (int8 STT, Q4_0 TTS, F16 codec), verify on desktop.
  3. On-device pipeline: VAD-gated STT, text pipeline, TTS with streaming, gapless playback.
  4. Transport: discovery, tie-break, framing, format negotiation, encryption, fallback order.
  5. Measurement: debug hooks log STT/TTS latency, RTF, memory, CPU and underruns; FLEURS-based WER harness.
  6. Iteration: fix what the numbers show. Idle CPU went from 67% to 0.3–1.6% and LITE memory from 1.9 GB to 688 MB this way.

Viability

  • Cost to deploy: runs on phones people already own; no network, server or licence fees. A LoRa bridge node costs about ₹1,900–3,200 (BOM estimate).
  • Maintainable: models are files; swapping a better open model needs no app rewrite (engine interfaces).
  • Scalable: the same packet format works for phone ↔ phone, phone ↔ ESP32 bridge, phone ↔ control-room gateway, and multi-hop relays.
SLIDE 5 · IMPACT AND BENEFITS

Impact and benefits

Template pointers: impact on target audience; social, economic, environmental benefits. Use icons per audience and a benefits grid.

Who it is for

Disaster response teams

NDRF/SDRF, district control rooms and volunteers coordinating when towers are down after floods, cyclones or landslides.

Coastal fishing communities

Boat-to-shore and boat-to-boat alerts in the local language over long-range low-bitrate links.

Rural and low-literacy users

Census 2011 literacy was about 74%; spoken output reaches people a text alert would miss.

Remote field staff

Forest, border, mining, rail track and power-line crews in poor-coverage areas.

Hearing-impaired users

Every message is also shown as text (size S to XL), with live captions while the sender speaks and vibration on alerts.

Events and crowds

Melas, pilgrimages and stadiums where the cellular network saturates.

Benefits

Social

  • Alerts in the listener's own language, spoken aloud.
  • The 10 languages cover roughly 85% of Indians by mother tongue (Census 2011), plus English.
  • Works for people who cannot read or cannot see a screen.
  • SOS carries location, so rescuers know where to go.

Economic

  • No new hardware for phone-to-phone use; a LoRa bridge node is about ₹1,900–3,200 (estimate).
  • No airtime or data charges; no cloud or licence fees.
  • Open-source stack can be adopted by state disaster agencies without vendor lock-in.

Environmental

  • About 60 bytes per sentence instead of tens of kilobytes: less radio time, lower battery drain on phones and relays.
  • Solar-powered low-power relay nodes become practical.
  • No data-centre inference.
Alignment: supports disaster-risk reduction and inclusive early warning (UN Early Warnings for All, SDG 11 and SDG 13) and India's CAP-based public alerting ecosystem (NDMA SACHET). The control-room gateway already parses CAP 1.2 alerts; connecting it to the live SACHET feed is the next step.

Scale: bar length = log10(bps) / 5.5. JSON carries readable field names and millisecond timestamps, so it is only a debugging format; binary is used between phones that negotiate it. LoRa at SF12/125 kHz carries roughly 250–300 bps and SF7 about 5.5 kbps, so the compressed frame fits even the slowest setting while voice does not.

Frames on the wire

TCP uses a 4-byte big-endian length prefix. BLE splits frames into chunks with a 3-byte [seq, index, count] header. The first byte tells the formats apart: { for JSON, 0x1X for binary. Hello is always JSON and announces protocol 2 (binary capable).

{ "type": "msg",
  "message": { "id": "7f3c…", "from": "device-A", "lang": "HI",
               "text": "बाढ़ का पानी बढ़ रहा है, ऊँचे स्थान पर जाएँ",
               "priority": "ALERT", "emotion": "URGENT", "ssml": false,
               "speechEndAt": 1790621234567, "sttDoneAt": …, "sentAt": … } }
other types: hello · partial · ack(receivedAt, playStartedAt) · ptt(talking) · ping/pong

FULL SYSTEM · UPGRADE IMPLEMENTATION PLAN

Implementation plan for each upgrade

Each upgrade lists its building blocks, steps, what it depends on, and the number that shows it worked.

A. Efficiency pack done

  • Built: per-language lazy TTS load, unload after 60 s idle (LITE) or 5 min (FULL), WavLM-free Mio init, F16 codec, VITS clause splitter, gapless playback, idle-CPU fixes.
  • Result: LITE idle PSS 688 MB, idle CPU 0.3–1.6%, 0 underruns on the 870.
  • Open: first audio is 0.6–0.95 s against a 0.6 s target. ONNX Runtime memory options are not exposed by the sherpa-onnx prebuilt AAR.

B. Compact binary packets done

  • Built: 16-byte header, per-script static dictionaries for all 10 languages, codec behind the frame interface, format negotiated in Hello, JSON kept for debugging and simple peers.
  • Result: median 62 B per sentence over 310 FLEURS sentences in a JVM unit test, better than the ≤ 80 B target. Caveats: the dictionaries were built from the same sentences (in-sample), and encryption (+20 B), an ALERT signature (+64 B), SOS location (+11 B) and link headers are not counted. Next: log real frame sizes on the phone and test on held-out sentences.

C. ESP32-S3 BLE ⇄ LoRa bridge compiled

  • Built: PlatformIO firmware for Heltec LoRa 32 V3 (LilyGO T3-S3 env too): NimBLE Nordic-UART service identical to the app's, SX1262 at 865.0625 MHz, 125 kHz, SF9 default, 14 dBm; 246-byte LoRa fragments, ACK with 3 retries and 4 s timeout. RAM 9.3%, flash 17.2%.
  • Next: flash two boards → check pin maps and the BLE tie-break → point-to-point test → range test (SF7 vs SF12) → enclosure.
  • Done when: 1 km line-of-sight delivery, sentence airtime < 1 s at SF9 measured on air.

D. Store-and-forward mesh partial

  • Built: firmware floods unseen ids with TTL−1 (TTL 3), 32-entry dedupe cache, random jitter.
  • Next: phones read TTL and dedupe received ids; phones relay; queue while no neighbour and forward when one appears; delivery receipts back to origin; destination addressing.
  • Depends on: C on hardware. Done when: 3-hop delivery demo with receipts.

E. One-tap SOS with location done

  • Built: SOS sheet with 6 localised templates, GNSS fix (reports NavIC in use), 11-byte location field, receiver speaks the coordinates. Shown in clips/05_sos.mp4.
  • Next: nearest named place from an offline gazetteer instead of raw coordinates.

F. Emotion and urgency transfer planned

  • Blocks: pitch/energy/speaking-rate features on the sender (no ML needed at first), rule-based urgency score, existing emotion nibble in the header, TTS style mapping (VITS emotion ids, Mio tags; already used for keyword-based URGENT).
  • Done when: listeners pick "urgent" vs "calm" correctly in an A/B test.

G. Cross-language delivery planned

  • Blocks: IndicTrans2 distilled (≈200M) int8 via CTranslate2 or ONNX; receiver-side translation into the listener's language before TTS; original text kept on screen.
  • Steps: convert model → benchmark on the 870 → enable only in FULL profile.
  • Done when: added latency < 700 ms per sentence; chrF reported on FLORES.

H. Sender's voice planned

  • Blocks: 10-second enrolment on the sender, speaker embedding (128 floats ≈ 512 bytes) sent once per session with consent, Indic-Mio voice conditioning on the receiver (today it uses fixed per-language voices built from FLEURS clips).
  • Done when: listeners recognise the sender more often than with the default voice.

I. Security partial

  • Built: X25519 pairing by QR code, ChaCha20-Poly1305 per packet with the header as associated data, Ed25519-signed ALERTs, replay guard, Keystore-wrapped identity.
  • Gaps: encryption is off until paired and applies to binary mode only; partial captions are sent in clear; the JSON path does no signature check; paired devices are not reloaded when the service restarts; the 8-byte tag gives a 2⁻⁶⁴ forgery bound.
  • Done when: unsigned ALERTs are shown as normal messages on every path; tampered packets are rejected.

J. Control-room gateway and CAP done

  • Built: Python gateway that joins the phone mesh over mDNS, logs to SQLite, and serves a live dashboard (peers, per-language counts, latency, approximate locations, broadcast). CAP 1.2 parser picks the right language block; sample cyclone and flood alerts included.
  • Next: LoRa link from the gateway, live SACHET feed, sign gateway broadcasts.

K. Friendlier, Indian-first interface done

  • Built: onboarding greeting in all 10 scripts, UI in 10 languages, language cards in native script, SOS chips, kolam motif, light and dark themes, credits to IISc ARTPARK, IIT Madras SPRING Lab and AI4Bharat.
  • Next: 5-person first-run test without help.
